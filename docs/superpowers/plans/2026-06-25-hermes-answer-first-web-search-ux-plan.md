# Hermes 联网答疑答案优先体验改造方案

日期：2026-06-25

状态：实施中。默认联网答疑入口已从严格研究链路转向 `web_assist_answer`：联网搜索被定位为知识加工时的外部材料补充器，而不是默认事实审判系统。本文档承接轻量联网答疑重构，不替代 provider 接入和检索质量方案；它专门解决“答案呈现像调试报告、免责声明过多、检索过程压过读者体验”的产品问题。

关联文档：

- `docs/superpowers/plans/2026-06-25-hermes-lightweight-web-qa-refactor-plan.md`
- `docs/superpowers/plans/2026-06-21-hermes-contract-lite-web-research-design.md`
- `docs/superpowers/plans/2026-06-20-hermes-web-research-pipeline-upgrade-plan.md`

## 0. 当前问题

Hermes 现在已经能联网、能展示来源、能保留 trace，但默认体验仍偏工程调试：

1. 主答案里会出现“从搜索结果看”“本次搜索”“未找到官方”“建议进一步查阅”等过程性表述。
2. warning 会在检索过程、来源区、答案正文之间重复出现。
3. 检索详情里候选、线索、后端、摘要/全文等信息有价值，但默认展示会打断阅读。
4. 答案容易变成证据审计报告，而不是直接回答问题。
5. 模型引用错编号时，系统能修复，但这个 warning 被用户看到，会降低信任。
6. 对弱来源或摘要来源，系统倾向于先解释限制，再回答问题。

用户真实目标不是看 Hermes 怎么想，而是得到问题的答案。搜索过程应该可追溯，但不能抢占主阅读路径。

## 1. 目标体验

默认阅读路径：

```text
用户问题
-> 直接答案
-> 关键要点
-> 正文内可点击引用
-> 检索详情（可展开）
```

默认不展示：

- planner 状态
- 查询词列表
- 候选网页
- clue/rejected source
- provider backend
- `summary_only_pages`
- `extract_backend`
- citation repair warning
- evidence critic 内部动作

这些信息仍保留在“检索详情”中，供用户主动排查。

## 1.1 当前实施决策

默认产品入口：

```text
web_assist_answer / async_web_assist_answer
```

职责：

1. 搜索网页作为外部理解材料。
2. 选择少量有用摘要或网页正文。
3. 生成答案优先的解释、背景、对比、观点整理。
4. 保留内联引用和来源 metadata。

非默认严格链路：

```text
research_answer / async_research_answer
```

只在用户明确要求严谨核验、官方证据、当前事实、法律/医疗/金融等高风险判断时使用。默认工作台不再走 evidence critic、repair search 和多轮证据审判。

当前默认边界：

| 项目 | web assist 默认 |
|---|---|
| 搜索 query | 最多 3 个 |
| 每个 query 结果 | 最多 6 条 |
| 候选池 | 最多 12 条 |
| 普通解释题全文抽取 | 默认不抽，摘要足够即回答 |
| 高风险/强时效/详细问题全文抽取 | 最多 2 页 |
| evidence critic | 默认不跑 |
| 失败处理 | 用可用摘要/本地材料回答，不把系统失败写进正文 |

## 2. 产品原则

### 2.1 答案优先

主答案第一段必须直接回答用户问题。

错误示例：

```text
根据现有搜索结果，目前不能确认……
```

更好示例：

```text
不能简单说 DeepSeek 是基于华为芯片训练的。公开信息更像是：核心模型训练、后训练、推理适配是三件事。
```

### 2.2 过程不进正文

正文禁止出现这类系统过程语：

- 从搜索结果看
- 本次搜索显示
- 目前检索到
- 未找到官方
- 以上信息来自
- 建议进一步查阅
- 搜索摘要显示

这些属于检索元信息，应进入 trace 或详情面板。注意，这里禁止的是过程表达，不是禁止边界判断。比如“未找到官方”不应作为搜索过程出现，但“该说法尚不能视为官方确认”可以作为答案的一部分出现。

### 2.3 不确定性内化为语义边界

来源弱时，不写样板免责声明，而是降低结论力度。必要的不确定性可以保留，但必须表达为答案边界，而不是系统反思。

错误示例：

```text
注意：以上信息完全来自 CSDN 博客摘要，属于二次来源，未找到官方文档。
```

更好示例：

```text
如果只看公开报道，能确认的是模型对华为昇腾芯片有适配和部分后训练案例；不能据此推出所有 DeepSeek 核心模型都由华为芯片完成训练。
```

### 2.4 信息边界表达合同

正文可以表达不确定性，但只能服务用户理解事实边界。

禁止：

- 从目前搜索结果看……
- 本次搜索没有找到……
- 资料来源较少……
- 建议进一步查阅……
- 以上信息完全来自……

允许：

- 公开信息只能支持 A，不能推出 B。
- 该说法目前不能视为官方确认。
- 这更适合作为行业传闻，而不是已证实事实。
- 如果问的是当前本地项目，应以本地仓库和配置为准。

边界说明必须满足三条：

1. 直接说明“能确认什么、不能确认什么”。
2. 不描述搜索过程、系统失败或模型修复动作。
3. 和答案主结论写在一起，不单独变成“注意/免责声明”段落。

### 2.5 审计能力保留，但默认收起

Hermes 的优势是可追溯。这个能力不能删，但应该分层：

| 层级 | 默认展示 | 内容 |
|---|---|---|
| 主答案 | 是 | 直接结论、解释、必要引用 |
| 正文内引用 | 是 | 关键事实旁的可点击来源 |
| 检索摘要卡 | 是，极简 | 联网完成、引用来源数、耗时、最多三个采用来源芯片 |
| 来源聚合入口 | 是，极简 | 例如“引用来源”，点击后展开实际引用来源 |
| 检索详情 | 否，折叠 | 查询词、候选、线索、未采用、warnings、backend、timings |
| 开发日志 | 否 | citation repair、critic fallback、provider error stack |

## 3. 回答生成合同

### 3.1 主答案结构

普通答疑默认结构：

```text
直接结论。

1. 要点一
2. 要点二
3. 要点三
```

复杂判断题默认结构：

```text
直接判断。

关键区别：
- A 是什么
- B 是什么
- 它们为什么容易混淆
- 当前能确认到什么，不能确认什么
```

不要默认输出：

- “依据分成以下几点”
- “注意”
- “免责声明”
- “若需精确信息请进一步查询”
- “本次搜索没有找到”

### 3.2 引用渲染合同

引用只服务答案，不服务检索展示。

规则：

1. 不在文末默认铺一长串参考网站。
2. 主答案里的关键事实使用内联可点击引用，点击即可打开对应网页或来源详情。
3. 多个来源支撑同一事实时，默认聚合成一个引用控件，不把 `[W1][W2][W3]` 全部暴露在正文里。
4. 主答案里每个关键事实最多展示 1 个主引用控件；更多支撑来源进入该控件的展开层。
5. 底部只保留一个轻量来源聚合入口，例如“引用来源”或“3 个引用来源”，点击后展开实际引用来源。
6. 只有实际使用的来源进入来源聚合入口；候选、线索、未采用来源只在检索详情里。
7. 如果来源全部是弱来源，仍可回答低风险解释题，但不要把传闻写成事实。
8. 如果是强事实问题且没有可靠来源，答案应直接说“不能确认”，然后给出可确认的部分。

内部合同：

1. 后端和模型内部仍使用稳定引用编号，例如 `[W1]`、`[K1]`。
2. `sources` metadata 是前端渲染的事实源，引用编号只用于定位，不直接等同于用户界面文案。
3. 前端把正文里的稳定 ref 映射为来源控件，默认渲染为链接图标、小号来源按钮或脚注气泡。
4. 网页来源点击后打开 URL 或来源浮层；本地知识来源点击后打开对应 capture、card 或知识详情。
5. 多来源支撑同一事实时，前端展示一个聚合控件，展开后显示主来源和补充来源。
6. 复制、保存笔记、做卡片时，应保留可用来源信息：可以转成 Markdown 链接，也可以随 metadata 保存；不能因为 UI 隐藏 `[W1]` 就丢失来源。

内联引用展示建议：

```text
DeepSeek-V3/R1 的公开训练信息更多指向 NVIDIA H800 集群训练。〔来源〕
```

或图标式：

```text
DeepSeek-V3/R1 的公开训练信息更多指向 NVIDIA H800 集群训练。链接图标
```

实现上用现有图标库渲染链接图标和小号数字气泡。用户点击后看到：

```text
主要来源：DeepSeek-V3 Technical Report
补充来源：CGTN / ChinaDaily / TechWeb
```

### 3.3 禁止把修复动作暴露给读者

这类 warning 不应出现在主阅读路径：

- 模型返回了未提供的来源编号
- 已改用实际可用来源编号
- 模型回答未引用已采用来源
- 已补上可验证来源编号
- citation repair

它们应进入：

- `research_trace.warnings`
- 检索详情
- 日志
- eval 统计

## 4. 检索与摘要/全文取舍

### 4.1 总原则

代码定上限，LLM 定取舍。

代码负责：

- query 数上限
- 候选池上限
- 抽取页数上限
- URL 安全
- 去重
- 引用编号
- trace

LLM 负责：

- 哪些候选和问题相关
- 哪些来源值得全文读取
- 摘要是否足以回答
- 来源限制如何影响答案力度

### 4.2 摘要可用的情况

满足全部条件时，摘要可以作为有限材料：

1. 低风险问题：概念解释、关系、区别、普通背景介绍。
2. 不涉及当前数值、价格、排名、政策、法律、医疗、金融建议。
3. 至少有 2 个信息量较足的独立摘要，或 1 个明显权威来源摘要。
4. 摘要能直接回答用户问题。

例子：

- “人工智能和深度学习的关系是什么？”
- “什么是 RAG？”
- “Harness engineer 大概是什么意思？”

### 4.3 必须全文读取的情况

以下情况默认全文读取：

1. 公司、项目、产品、开源仓库的正式定位。
2. 当前/最新/现任/今天/今年。
3. 价格、市值、销量、排名、影响因子、版本差异。
4. 法律、医疗、金融、投资判断。
5. 用户问“是否基于”“是否由谁训练”“是否官方确认”这类真假判断。
6. 搜索摘要互相矛盾。

弱来源不是“默认全文读取”的理由。候选来源主要是 CSDN、知乎、公众号、百家号、SEO 聚合站时，应进入弱来源策略，而不是消耗全文抽取预算去读低质量页面。

### 4.4 弱来源使用策略

弱来源默认降级为线索，不默认进入答案依据。

策略：

1. 如果候选池主要由博客、知乎、CSDN、公众号、百家号、SEO 聚合站组成，先修正查询词，优先寻找官方文档、技术报告、论文、GitHub、主流媒体或行业媒体。
2. 弱来源可以帮助发现关键词、主体名称、争议点和更可靠来源线索。
3. 只有在问题低风险、摘要信息足够、且用户问的是概念解释或普通背景时，弱来源才可有限使用。
4. 弱来源不能支撑强结论，例如“官方确认”“一定基于”“销量第一”“投资可行”。
5. 不为了弱来源本身默认全文读取；只有它能明显补足答案、或用户明确问某篇文章/某个观点时，才抽取全文。
6. 弱来源被有限使用时，答案必须降低结论力度，但不输出样板免责声明。

### 4.5 来源分层

面向答案的来源分层：

| 类型 | 默认用途 |
|---|---|
| 官方/技术报告/GitHub/论文 | 可支撑强事实 |
| 主流媒体/行业媒体 | 可支撑报道事实 |
| 百科/数据库 | 可支撑背景介绍 |
| 博客/知乎/CSDN/公众号 | 线索或低风险解释，不支撑强结论 |
| 社交媒体/LinkedIn/传闻站 | 只能表述为传闻或线索 |

注意：这不是硬编码拒绝列表，而是给 LLM 的来源质量上下文。代码只做安全、去重、上限、编号和引用校验。

## 5. UI 改造方案

### 5.1 默认答案区

默认只展示：

1. 用户问题。
2. 主答案。
3. 正文内可点击引用。
4. 极简联网卡。
5. 极简来源聚合入口。

极简联网卡：

```text
联网搜索完成 · 3 个引用来源 · 55 秒
引用来源
检索详情
```

默认卡片不展开长来源列表；最多可显示 1-3 个被答案实际引用的来源芯片。候选、线索、未采用来源都不进入默认卡片。

来源聚合入口示例：

```text
链接图标 + 引用来源
```

点击后展开：

```text
引用来源
[W1] DeepSeek-V3 Technical Report · arxiv.org
[W2] DeepSeek unveils new AI model adapted for Huawei chips · news.cgtn.com
[W3] DeepSeek rumored to train AI model with Huawei chips · linkedin.com
```

这个展开层是用户主动查看的来源清单，不再作为答案文末默认长列表。数量口径只统计实际引用/采用来源，不统计所有候选网页。

### 5.2 检索详情

展开后展示：

- 检索阶段
- 查询词
- 候选网页
- 已读取页面
- 摘要来源
- 未采用来源
- warnings
- provider status
- timings

详情面板是给排查和信任建立用的，不是默认阅读内容。

### 5.3 来源展示区

不再默认渲染长篇文末参考来源区。改为两层：

第一层：正文内引用控件。

```text
DeepSeek 的公开训练信息更多指向 NVIDIA H800 集群。〔来源〕
```

第二层：底部聚合入口。

```text
引用来源
```

点击后再展示完整来源列表。这个列表只包含实际支撑答案的来源，不包含候选、线索、未采用来源。

不显示 warnings。

## 6. 后端改造方案

### 6.1 Synthesis prompt 收敛

文件：

- `bridge/research/synthesis.py`

改造：

1. 强化“答案优先”规则。
2. 禁止检索过程语进入正文。
3. 弱来源时降低结论力度，不输出样板免责声明。
4. 明确“来源质量说明属于 trace，不属于正文”；必要的事实边界必须写成答案语义边界。
5. 对真假判断题要求区分：预训练、后训练、微调、推理适配、硬件兼容。

### 6.2 Light web QA source selection

文件：

- `bridge/research/light_web_qa.py`

改造：

1. LLM 选源 prompt 加入“是否需要全文”的结构化输出。
2. 输出字段：

```json
{
  "selected_refs": ["W1", "W3"],
  "need_extract_refs": ["W1"],
  "answerable_from_summary_refs": ["W3"],
  "reason": "..."
}
```

3. 对强事实问题自动提高可靠来源的全文读取优先级。
4. 对弱来源候选默认降级为线索，优先寻找更可靠来源。
5. 对摘要足够的低风险问题，允许不抽取全文。

### 6.3 Source quality hints

文件：

- `bridge/research/search_infra.py`
- `agents/source_registry.py`
- `config/source_preferences.yaml`

改造：

1. 只产出 source quality hints，不做最终语义裁判。
2. 标注：
   - official
   - technical_report
   - documentation
   - mainstream_media
   - encyclopedia
   - blog
   - social
   - rumor
   - aggregator
3. 这些 hint 进入 synthesis prompt，帮助模型控制语气。

### 6.4 Citation repair 降噪

文件：

- `bridge/research/synthesis_guard.py`

改造：

1. citation repair warning 保留在 trace。
2. 不进入默认前端参考来源区。
3. 如果频繁出现，作为 eval 失败信号，而不是用户可见提示。

## 8. DeepSeek 网页端可借鉴点

借鉴：

1. 先给结论。
2. 按用户关心的问题维度组织答案。

1. 不把传闻写成确定事实。
2. 不牺牲来源可追溯。
3. 不隐藏真实来源质量。
4. 不把弱来源包装成官方确认。

Hermes 的目标不是变得更敢说，而是变得更会回答。

## 9. 验收样例

### 9.1 DeepSeek 华为芯片问题

问题：

```text
Deepseek 是基于华为芯片训练的吗？
```

期望答案形态：

```text
不能简单说 DeepSeek 是基于华为芯片训练的。更准确地说，公开信息里要区分三件事：核心模型预训练、后训练/微调、推理适配。

DeepSeek-V3/R1 这类已公开技术信息更多指向 NVIDIA H800 等 GPU 集群训练；而关于华为昇腾的报道，主要集中在后续模型适配、推理部署，或部分后训练案例。也就是说，DeepSeek 和华为芯片之间确实有适配和训练相关报道，但这不等于 DeepSeek 的核心模型都是基于华为芯片训练出来的。
```

不应出现：

- 从搜索结果看
- 本次搜索
- 目前检索到
- 未找到官方
- 建议进一步查阅
- 模型返回了未提供的来源编号

### 9.2 Hermes 是什么

问题：

```text
Hermes 智能体是什么？
```

期望答案形态：

```text
Hermes 智能体可以理解为一个面向个人知识、自动化和多工具协作的 AI 代理工作台。它不是单纯聊天机器人，而是把本地知识库、联网检索、任务执行、内容整理和保存复用串在一起。
```

如果只找到弱第三方来源：

```text
如果问的是当前这个本地 Hermes 项目，应优先以本地仓库和配置为准；第三方部署教程只能作为线索，不能定义项目本身。
```

不应先说：

```text
从搜索结果看……
```

### 9.3 人工智能和深度学习

## 11. 非目标

本方案不做：

1. 新增严格研究模式。
2. 新增专业金融/法律/医疗工具。
3. 把所有搜索结果都交给 LLM。
4. 删除 trace。
5. 牺牲引用和可追溯性。
6. 让模型无来源自由发挥。

## 12. 成功定义

用户看到的是：

```text
答案
来源
可展开检索详情
```

而不是：

```text
系统搜索过程
候选来源状态
证据限制声明
答案
重复 warnings
```

Hermes 应保留工程可观测性，但默认交付的是信息答案。最终产品形态是：

```text
答案优先的信息工作台，带可追溯来源和可展开检索过程。
```
