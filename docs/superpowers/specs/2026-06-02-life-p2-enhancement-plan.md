# Life Assistant P2 增强方案

## 定位

P2 不再继续堆硬编码规则，而是把 Life Assistant 从“能记录、能提醒、能展示”推进到“能理解生活模式、能解释判断、能给出健康建议”的阶段。

核心原则：

- 规则负责底线：时间表、去重、限流、状态回写、数据不脏。
- LLM 负责模糊理解：用户自然表达、生活语义、周报分析、长期决策复盘。
- 记忆负责连续性：偏好、作息模式、提醒反馈、阶段目标只作为上下文，不强行替用户做结论。

## P2.1 智能周报

目标：每周推送 600 字以内的生活分析报告，而不是纯数字汇总。

输入：

- 本周睡眠记录和醒来/入睡节律。
- 饮食记录内容、时间和缺口。
- 喝水次数。
- 运动完成/跳过/改期记录。
- 久坐总时长和超标时长。
- Life 记忆中的生活模式和提醒反馈。

输出结构：

- 本周总判断：一句话。
- 睡眠/饮食/运动/久坐四个维度分析。
- 下周一个最重要建议。
- 需要补记的数据缺口。

边界：

- 不做医疗诊断。
- 不写长篇报告。
- 不把偶然一天的数据说成稳定规律。

## P2.2 记忆驱动提醒

目标：提醒不是机械重复，而是参考你的习惯和近期反馈。

可用记忆：

- 作息：常见入睡/醒来时间。
- 饮食：常见吃饭时间、容易漏记的餐段。
- 运动：更容易接受的运动时间、常做运动类型。
- 久坐：容易超标的时段。
- 文案：你不喜欢太长、太机械、太打扰的提醒。

机制：

- 记忆只影响候选提醒排序、文案和追问方式。
- 不能因为记忆跳过强提醒底线，例如久坐。
- 每次使用记忆都记录 decision trace，方便看板解释“为什么这么提醒”。

## P2.3 长期决定复盘升级

目标：长期决定不只是定时提醒，而是变成可追踪的生活/成长决策系统。

能力：

- 用户创建长期决定时，必须有下次复盘时间；没有就追问。
- 支持修改复盘时间。
- 支持复盘时记录 outcome：继续、调整、完成、放弃。
- 支持把复盘结论写回长期记忆。

看板：

- 活跃长期决定列表。
- 下次复盘时间。
- 最近一次复盘结论。
- 逾期未复盘提示。

## P2.4 自动补记追问

目标：睡眠和饮食缺记录时，系统主动追问，但不过度打扰。

规则底线：

- 睡眠：每日固定时间检查是否缺完整睡眠时长。
- 饮食：每日固定时间检查是否完全没有饮食记录。

LLM 增强：

- 根据上下文判断用户是不是已经说过相关信息但没被结构化记录。
- 追问时只问缺口，不重复问已有信息。
- 用户补一句自然语言后，自动归并到对应记录。

## P2.5 数据修复工作台

目标：把数据质量从“出问题手动 SQL”升级成可审计的修复流程。

能力：

- `life_repair.py` dry-run 列出候选。
- 看板显示待修复项数量。
- 高风险项只建议，不自动改。
- 安全项可一键 apply。

安全项：

- 卡住的 `sending` 提醒。
- 明确 superseded 的重复提醒。

高风险项：

- 重复睡眠记录。
- 饮食时间/内容疑似解析错误。
- 跨夜久坐切分异常。

## 建议执行顺序

1. 先做 P2.1 智能周报，因为它最直接提升价值感。
2. 再做 P2.2 记忆驱动提醒，让提醒更像懂你的助手。
3. 然后做 P2.3 长期决定复盘升级。
4. 最后做 P2.5 数据修复工作台，把维护成本降下来。

## 验收标准

- 周报 600 字以内，但包含分析和建议。
- 至少 3 类提醒能看到记忆影响 trace。
- 长期决定支持创建、改期、复盘、关闭。
- 数据修复默认 dry-run，不会静默改库。
- Life 看板能说明系统为什么提醒、为什么没提醒、哪些数据缺口还没闭环。
