# Hermes Knowledge 一页纸速记

更新日期：2026-06-02（口径更新：2026-11）

## 项目一句话

Hermes Knowledge 是一个基于 Hermes Agent Framework、SQLite 和自研 Web 前端的 AI-native 个人知识工作台。它把微信、网页、文件、小红书图文等材料变成可审阅草稿，用户确认后入库，再通过资料 → 卡片 → 专题的结构，以及 evidence-first RAG、自研卡片板和知识图谱，完成知识维护、问答、卡片沉淀和关系浏览。

## 我解决的问题

个人知识库常见问题不是没有材料，而是材料进来后不可复用：

- 收藏入口分散，微信、网页、文件、图片各走各的。
- 原文太长，缺少适合自己复用的整理稿。
- 资料、卡片、专题之间的关系不稳定，回看时找不到同一条思路。
- RAG 回答难追溯，不知道用了哪些材料。
- 知识卡片容易重复，专题关系不直观。
- 旧知识沉没，没人主动带回来复习。

## 产品闭环

```text
输入材料
  -> Capture 生成草稿
  -> 用户确认入库
  -> Library 维护结构和索引
  -> RAG evidence-first 回答
  -> Topic/Cards 组织专题并沉淀知识卡片
  -> 卡片板 + 知识图谱浏览关系
  -> Review 每天讲一个知识点
```

## 关键设计

### 1. 用户确认入库

AI 先生成草稿，用户可以展开、修改、确认。只有回复“存库”后才写入知识库，避免错误内容污染长期知识库。

### 2. raw 和 capture 分层

raw 是证据归档区，capture 是日常阅读区。这样既保留原文可追溯性，又不让原始噪音影响阅读和检索。

### 3. Library 做知识库管家

Library 不负责改写观点，而是负责数据健康：DB 与文件一致、properties 完整、长文有目录和章节、embedding 可用。

### 4. RAG 对用户保持简单

用户只问问题，不选复杂模式。内部采用 evidence-first retrieval：先从资料/章节找证据，再沿专题、卡片和资料关系扩展；卡片按来源数与引用数加权，不无条件置顶。输出必须有可读来源。

### 5. Cards 存可复用知识对象

Cards 不是摘要库，也不是纯观点库。卡片固定四类：洞察/金句、新知/概念、方法/框架、避坑/边界；标准是能否被独立复用。专题（Topic）负责把跨资料的卡片组织成长期问题。

## Agent / 工具分工

| 模块 | 一句话职责 |
| --- | --- |
| Hermes 主 Agent | 统一入口和工具路由 |
| Capture | 提取材料，生成可审阅草稿 |
| Library | 维护知识库、DB、目录、章节、embedding |
| RAG | evidence-first 检索，按来源与引用给卡片加权，保留引用 |
| Topic | 组织专题视图，聚合资料、卡片和开放问题 |
| Cards | 生成四类可复用知识卡片 |
| Cards Board / Graph | 浏览已确认卡片，展示卡片—资料—专题关系 |
| Review | 每天讲一个点，防止知识沉没 |

## 最能体现 AIPM 能力的点

- 不只是接模型，而是把 AI 能力产品化成工作流。
- 明确区分 LLM 判断和确定性代码边界。
- 针对微信字数限制设计了预览和文件输出。
- 针对 AI 不可靠性设计了草稿确认、引用追溯和数据修复。
- 针对知识复用设计了专题、卡片、卡片板和知识图谱，而不是只做搜索。
- 针对真实使用不断迭代：长文、小红书图文、重复卡片、引用不全、卡片板与图谱可读性。

## 面试中不要说过头

稳妥说法：

- 这是个人可用的 v0.1 产品原型。
- 已经跑通知识管理主链路。
- 仍需要更多真实样本验证多模态和超长文鲁棒性。
- RAG 已有 evidence-first 检索、图扩展和引用追踪；已完成一次 28 条 query 的 DashScope 重跑（Recall@5 0.389→0.833，G3 1.0，负样本 9/10），答案质量还要持续评测。
- 如果要给其他人用，还需要安装配置、运行观测、错误恢复和权限隔离。

不要说：

- 已经是成熟商业产品。
- 所有多模态材料都稳定支持。
- RAG 永远能完整准确回答。
- Cards 能自动沉淀所有有价值知识。

## 30 秒口播

我做了一个 AI-native 个人知识工作台 Hermes Knowledge。它把微信里的文章、文件或图文材料接进 Web 工作台：Hermes 先生成可审阅草稿，我确认后入库。入库后 Library 会补目录、章节、属性和 embedding；之后我可以基于知识库问问题，RAG 会先找证据、再按来源和引用给卡片加权，回答带来源；多篇材料形成关系时，Cards 会沉淀成知识卡片，并用自研卡片板和知识图谱展示关系。这个项目的重点不是单篇总结，而是把材料进入、确认、结构维护、可追溯问答、知识卡片和回顾串成一个完整闭环。
