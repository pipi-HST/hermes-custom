# Reset local personal Knowledge data without deleting operational configuration

Hermes Knowledge supports a local reset that clears personal Knowledge content while preserving operational configuration. The reset deletes rows from Knowledge content, draft, reading, review, embedding, graph, run/audit, write-job, and legacy `life_*` residual tables in the database resolved from `config.yaml` (`database.path`, typically `<repo>/data/captures.db`), preserving the database schema instead of rebuilding the DB. It may delete the legacy vault directory (default `~/Obsidian/hermes-vault`) and Knowledge content backup directories only after dry-run review and explicit confirmation. It preserves `config.yaml`, API keys, model settings, scheduler/LaunchAgent configuration, normal logs, and the independent Life database (default `~/hermes-life/data/life.db`).

The reset script refuses to delete a filesystem root, the user's home directory, or the repository root; the legacy vault and backup targets must be explicit subdirectories. On Windows the scheduler is the Task Scheduler, on macOS the LaunchAgent — the boundary is the same: reset personal content, never operational configuration.
